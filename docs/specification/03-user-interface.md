# Интерфейс пользователя

## Общая концепция

Пользовательский интерфейс iikoAssistant представляет собой адаптивное веб-приложение,
доступное с нескольких компьютеров и мобильных устройств.

Основной принцип взаимодействия с системой - диалоговый интерфейс с возможностью выбора
готовых сценариев получения информации.

Пользователь может взаимодействовать с системой двумя способами:
1. Выбирать необходимые запросы с помощью последовательной навигации по категориям и параметрам
2. Вводить запросы в текстовое поле чата

На первых двух итерациях обработка пользовательских запросов осуществляется посредством заранее
определенных сценариев. Поддержка произвольных запросов на естественном языке с использованием
LLM планируется в рамках третьей итерации.

## Структура страницы

Основная страница приложения представляет собой единый экран, состоящий из нескольких элементов:

1. Шапка приложения
   - Название приложения
   - Информация о текущем подключении к системе iiko
2. Боковая панель навигации
   - Располагается в левой части интерфейса на настольных устройствах
   - Содержит основные категории доступных запросов:
      - Продажи и выручка
      - Складской учет
      - Закупки и поставщики
      - Анализ меню и рентабельности
      - Персонал и эффективность работы
      - Фонд оплаты труда
   - При выборе категории пользователю отображаются доступные в ней запросы
   - Навигация осуществляется последовательно
   - Для возврата к предыдущему шагу предусматривается возможность навигации по ранее выбранным пунктам
3. Область диалога
    - Располагается справа от боковой панели и занимает оставшееся доступное пространство экрана
    - Отображает историю взаимодействия пользователя с системой
    - Содержит отправленные пользователем запросы и ответы iikoAssistant
    - Ответы могут включать текстовую информацию, числовые показатели, списки и таблицы
    - При необходимости система отображает дату и время, к которым относятся данные, а также  
время их последнего обновления
    - Новые сообщения добавляются в конец диалога
4. Поле ввода сообщения
   - Предназначено для ввода произвольных текстовых запросов
   - Содержит кнопку отправки сообщения
   - Поддерживает отправку сообщения нажатием соответствующей кнопки или клавиши Enter
   - На первых двух итерациях поддерживается обработка только предусмотренных системой сценариев запросов
Произвольные запросы, которые не могут быть обработаны, сопровождаются соответствующим уведомлением
и предложением воспользоваться панелью категорий

## Пустое состояние страницы

При первом входе пользователя в приложение, когда история диалогов отсутствует, система
отображает приветственный экран, содержащий:
- Приветственное сообщение
- Краткое описание назначения системы и доступных возможностей
- Несколько кнопок с примерами наиболее ожидаемых запросов
- Возможность перейти к выбору запроса через боковую панель категорий
- Поле ввода сообщения

К наиболее ожидаемым запросам относятся:
- "Показать выручку за сегодня"
- "Показать средний чек за сегодня"
- "Показать критические остатки на складе"
- "Показать ФОТ за текущий месяц"

По нажатии на такую кнопку система автоматически формирует соответствующий запрос и
отправляет его на обработку.

Состав наиболее ожидаемых запросов может изменяться по мере расширения функциональности приложения.

## Сценарий взаимодействия с системой

Основной сценарий получения информации предполагает последовательный выбор
пользователем необходимых параметров.

Пример: получение выручки за текущий день
1. Пользователь выбирает категорию "Продажи и выручка"
2. Система отображает доступные запросы в выбранной категории
3. Пользователь выбирает "Выручка за период"
4. Система предлагает выбрать период:
   - Сегодня
   - Вчера
   - Текущая неделя
   - Прошлая неделя
   - Текущий месяц
   - Прошлый месяц
   - Произвольный период
5. Пользователь выбирает "Сегодня"
6. Система автоматически формирует запрос "Выручка за сегодня" и отправляет его на обработку
7. В диалоговом окне справа, т.е. от пользователя, появляется сообщение "Выручка за сегодня"
8. Backend выполняет соответствующий сценарий получения данных из iiko
9. Результат обработки отображается в области диалога слева, т.е. от системы
10. В дальнейшем пользователь может вручную написать в чат "Выручка за сегодня" для получения
аналогичного результата

## Отображение результатов

Результаты выполнения запросов отображаются непосредственно в области диалога. Формат
зависит от типа полученных данных:
- Отдельные числовые показатели отображаются в виде выделенных значений
- Несколько связанных показателей могут отображаться в виде списка
- Данные, предполагающие сравнение нескольких элементов, могут отображаться в виде таблиц

Представление результатов должно обеспечивать быстрое восприятие информации без необходимости
изучения сложных аналитических интерфейсов.

Для каждого ответа предусматривается отображение периода, к которому относятся данные.
При наличии информации о времени синхронизации с iiko оно также отображается пользователю.

## Обработка некорректных данных и неподдерживаемых запросов

Если пользователь вводит запрос, который не соответствует ни одному из поддерживаемых сценариев,
система отображает уведомление о невозможности его обработки. В уведомлении предлагается
воспользоваться панелью категорий для выбора доступного запроса. Если для выполнения выбранного
сценария недостаточно параметров, система запрашивает у пользователя недостающую информацию.
При возникновении ошибок получения или обработки данных система отображает понятное пользователю
сообщение без раскрытия технических подробностей.

## Адаптивность интерфейса

Интерфейс должен обеспечивать корректную работу на настольных компьютерах и мобильных устройствах.
При изменении размера экрана предусматривается адаптация расположения элементов:
- На настольных устройствах панель категорий располагается слева от области диалога
- На мобильных устройствах она скрывается в гамбургер-меню слева от области диалога
- Область диалога занимает доступное пространство экрана
- Поле ввода сообщения остается доступным в нижней части экрана
- Табличные данные должны адаптироваться к ширине экрана или предусматривать горизонтальную прокрутку

Функциональность интерфейса должна оставаться одинаковой независимо от используемого устройства.
