# Контроль операций и потерь

## UC-32. Число отмен за период

| Поле        | Описание                                                                                                 |
|-------------|----------------------------------------------------------------------------------------------------------|
| Инициатор   | Владелец заведения                                                                                       |
| Цель        | Получить информацию о количестве отмененных заказов за выбранный период времени                          |
| Предусловия | Доступно подключение к iiko. В системе имеются данные об операциях с заказами, включая отмененные заказы |
| Триггер     | Пользователь выбирает запрос "Число отмен за период"                                                     |
| Итерация    | 1                                                                                                        |

### Основной сценарий

| № | Действие пользователя                           | Действие системы                                                                 |
|---|-------------------------------------------------|----------------------------------------------------------------------------------|
| 1 | Выбирает категорию "Контроль операций и потерь" | Отображает доступные запросы                                                     |
| 2 | Выбирает "Число отмен за период"                | Отображает варианты выбора периода                                               |
| 3 | Выбирает период                                 | Формирует запрос с указанным периодом                                            |
| 4 | -                                               | Получает из iiko данные об отмененных заказах за выбранный период                |
| 5 | -                                               | Определяет общее количество отмен за выбранный период                            |
| 6 | -                                               | Группирует отмены по датам                                                       |
| 7 | -                                               | Рассчитывает количество отмен за каждый день выбранного периода                  |
| 8 | -                                               | Отображает общее количество отмен и их распределение по дням за выбранный период |

### Альтернативные сценарии

- A1. Пользователь выбирает произвольный период. Система предлагает указать начальную и конечную даты
- A2. За выбранный период отсутствуют отмененные заказы. Система сообщает об отсутствии отмен
- A3. Не удалось получить данные из iiko. Система отображает сообщение об ошибке
- A4. За выбранный период обнаружены отмены без указания причины. 
Система учитывает такие отмены в общем количестве, отдельно отмечая отсутствие причины
- A5. Один заказ отменялся несколько раз или повторно проводился через систему.
Система учитывает отмены согласно правилам регистрации операций в iiko

### Постусловия

В истории диалога отображено общее количество отмен за выбранный период с разбивкой по дням.

_Примечания. Уточнить у заказчика:_

- _Что считать отменой: отмененный заказ целиком, удаленную позицию или отмененную оплату?_
- _Нужно ли отображать причины отмен и сотрудников, выполнивших отмену?_

| № | Действие пользователя                           | Действие системы                                                                                 |

| 5 | -                                               | Определяет общее количество операций возврата                                                    |

### Альтернативные сценарии

- A1. Пользователь выбирает произвольный период. Система предлагает указать начальную и конечную даты
- A2. За выбранный период отсутствуют возвраты. Система сообщает об отсутствии операций возврата
- A3. Не удалось получить данные из iiko. Система отображает сообщение об ошибке
- A4. За выбранный период обнаружены частичные возвраты. 
Система учитывает их количество и фактически возвращенные суммы согласно данным iiko
- A5. По одной операции возврата зарегистрировано несколько платежных операций.
Система учитывает возврат согласно правилам учета операций в iiko

### Постусловия

В истории диалога отображена информация о количестве возвратов и общей сумме возвращенных денежных средств за выбранный период с разбивкой по дням.

_Примечания. Уточнить у заказчика:_

- _Учитывать только возвраты денежных средств или также возвраты отдельных позиций заказа?_
- _Как учитывать частичные возвраты: считать каждый как отдельную операцию или объединять в рамках одного заказа?_

## UC-35. Контроль списаний

| Поле        | Описание                                                                                                                            |
|-------------|-------------------------------------------------------------------------------------------------------------------------------------|
| Инициатор   | Владелец заведения                                                                                                                  |
| Цель        | Определить сотрудников, которые чаще всего проводят операции списания                                                               |
| Предусловия | Доступно подключение к iiko. В системе имеются данные об операциях списания, их датах, причинах и сотрудниках, выполнивших списания |
| Триггер     | Пользователь выбирает запрос "Контроль списаний"                                                                                    |
| Итерация    | 1                                                                                                                                   |

### Основной сценарий

| № | Действие пользователя                           | Действие системы                                                                                                |
|---|-------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| 1 | Выбирает категорию "Контроль операций и потерь" | Отображает доступные запросы                                                                                    |
| 2 | Выбирает "Контроль списаний"                    | Формирует запрос на получение данных обо всех операциях списания за весь доступный период                       |
| 3 | -                                               | Получает из iiko данные об операциях списания, включая даты, суммы и сотрудников, выполнивших списания          |
| 4 | -                                               | Группирует операции списания по сотрудникам                                                                     |
| 5 | -                                               | Рассчитывает общее количество списаний, выполненных каждым сотрудником                                          |
| 6 | -                                               | Сортирует сотрудников по количеству проведенных списаний в порядке убывания                                     |
| 7 | -                                               | Определяет сотрудников с наибольшим количеством операций списания                                               |
| 8 | -                                               | Отображает рейтинг сотрудников с указанием количества проведенных списаний и выделяет лидеров по числу операций |

### Альтернативные сценарии

- A1. За весь доступный период списания не проводились. Система сообщает об отсутствии операций списания
- A2. Не удалось получить данные из iiko. Система отображает сообщение об ошибке
- A3. У некоторых операций отсутствует информация о сотруднике, выполнившем списание.
Система учитывает такие операции отдельно в категории "Сотрудник не указан"
- A4. Несколько сотрудников провели одинаковое количество списаний. Система отображает их на одном уровне рейтинга
- A5. Один сотрудник провел списания по нескольким причинам. 
Система отображает общее количество списаний сотрудника без дублирования операций

### Постусловия

В истории диалога отображен рейтинг сотрудников по количеству проведенных операций списания 
за весь доступный период с указанием количества списаний каждого сотрудника 
и сотрудников с наибольшей частотой проведения таких операций.

_Примечание: Уточнить у заказчика, следует ли выделять сотрудников 
с аномально высокой частотой списаний для дальнейшей проверки?_
